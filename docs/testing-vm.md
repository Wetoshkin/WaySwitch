# Проверка в живом сеансе Wayland

Юнит-тесты не проверяют фактическое переключение раскладки и ввод в
приложения. Этот чек-лист предназначен для отдельной тестовой учётной
записи или VM с доступными устройствами ввода. Используйте вымышленный
текст; сохраните открытые документы перед проверкой.

## Подготовка

1. Установите пакет по [README](../README.md) и войдите в новый сеанс Wayland.
2. Настройте русскую и английскую раскладки. Проверьте их обычное
   переключение средствами рабочего стола.
3. Выполните `wayswitch doctor`. Устраните ошибки обязательных проверок.
4. В GNOME включите расширение WaySwitch и при необходимости войдите заново:
   `gnome-extensions enable wayswitch@siberia.ru`.
5. Откройте простой текстовый редактор и окно WaySwitch. Убедитесь, что
   одновременно работает только один экземпляр демона.

## Основные сценарии

| Действие | Ожидаемый результат |
|---|---|
| Набрать `ghbdtn ` в английской раскладке | `привет `, раскладка русская |
| Набрать `руддщ ` в русской раскладке | `hello `, раскладка английская |
| Двойной Shift после ошибочного слова | Исправлено последнее слово |
| Тройной Shift | Исправлена фраза |
| Двойной Shift сразу после автоматического исправления | Возвращён исходный текст |
| Повторить отмену одного слова до порога в настройках | Слово появилось в исключениях |
| Поставить паузу, набрать тестовую строку | Текст не изменяется |
| Заблокировать и разблокировать экран | События блокировки не перепечатываются |
| Отключить и подключить тестовую клавиатуру | Работа возобновляется без перезапуска |

Проверьте исправление при быстром наборе и зажатом Shift, а также в полях
с автодополнением. Отдельно проверьте исключения по приложениям и
распознавание полей пароля, используя вымышленный пароль. Если приложение
не сообщает тип поля, перед чувствительным вводом требуется пауза.

В GNOME дополнительно проверьте исправление выделенного текста,
транслитерацию и число прописью. В KDE — виджет панели; в Sway/Hyprland —
Waybar и автозапуск из конфигурации композитора.

## Диагностика

`wayswitch dry-run` показывает решения без перепечатки;
`wayswitch run --verbose` выводит подробный журнал. Перед ручным запуском
остановите экземпляр службы, например `systemctl --user stop wayswitch`,
если она управляется systemd. После проверки запустите её снова.

Оба диагностических режима могут раскрыть набранный текст. Не вводите
личные сведения и просмотрите журнал перед публикацией.

`python3 tests/e2e_vm.py` — отдельный сквозной сценарий, не часть pytest.
Запускайте его с пустым тестовым полем в фокусе; он эмулирует нажатия.

## Что приложить к отчёту

- Версии WaySwitch, дистрибутива и рабочего стола; тип сеанса Wayland.
- Имена и варианты раскладок, выбранный бэкенд из `wayswitch doctor`.
- Приложение, точные шаги, ожидаемый и фактический результат.
- Настройку задержки после смены раскладки, если её меняли.
- Диагностический вывод без личных данных.

Отправить отчёт можно в [GitHub Issues](https://github.com/Wetoshkin/WaySwitch/issues).

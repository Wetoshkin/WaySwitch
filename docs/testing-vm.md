# Проверка в живом сеансе Wayland

Юнит-тесты не проверяют фактическое переключение раскладки и ввод в
приложения. Этот чек-лист предназначен для отдельной тестовой учётной
записи или VM с доступными устройствами ввода. Используйте вымышленный
текст; сохраните открытые документы перед проверкой.

## Подготовка

1. Установите пакет по [README](../README.md) и войдите в новый сеанс Wayland.
2. Настройте русскую и английскую раскладки. Проверьте их обычное
   переключение средствами рабочего стола.
3. Выполните `wayswitch doctor`. Устраните ошибки обязательных проверок.
4. В GNOME включите расширение WaySwitch и при необходимости войдите заново:
   `gnome-extensions enable wayswitch@wetoshkin.github.io`.
5. Откройте простой текстовый редактор и окно WaySwitch. Убедитесь, что
   одновременно работает только один экземпляр демона.

## Основные сценарии

### Дополнительные источники ввода (issue №21)

Проверять на уже разрешённом стенде; этот чек-лист не разрешает запуск или
создание VM. В этом изменении живые сеансы перечисленных сред не проверялись.

| Настройка / действие | Ожидаемый результат |
|---|---|
| `de,ru,us`, затем `us,de,ru`, 4 и 5+ источников в средах с прямым IPC | Мастер завершается; ru/en исправляются и отменяются по исходным индексам |
| Выбраны de/fr/pl/uk/be или источник IBus | Нет автоматических исправлений, жестов изменения текста, преобразования выделения и обучения |
| Возврат из постороннего источника в ru/en | Работа возобновляется без Resume; старый буфер не переносится |
| Смена источника после пробела до отложенной замены, в том числе потеря владельца D-Bus | Поздней перепечатки нет |
| Несколько вариантов ru/en, включая Dvorak | Используется текущий вариант и первый противоположный язык в системном порядке |
| Установлена только одна раскладка / отсутствует ru или en | Настройка и запуск разрешены с предупреждением, изменения текста недоступны |
| GNOME: IBus-источник перед ru/en, выбран при старте | Индексы сохраняются; после возврата в ru/en исправления доступны через расширение |
| Umbriel: между ru/en две другие группы | Каждый шаг подтверждён, промежуточные события не отматывают состояние; при ошибке текст не удаляется |
| COSMIC | Используется фактическая карта wl_keyboard; сохраняется подтверждение после входа/разблокировки |
| labwc/Wayfire: 3–4 группы и обычный циклический хоткей | Сохраняется прежнее явное включение `track_hotkey`; учитываются все позиции |
| Fallback: неизвестная семантика хоткея, GNOME MRU 3+ или непроверяемые 5+ групп | Служба запускается пассивно, статус не предлагает неработающее ручное исправление |

Для каждого живого прогона записать версию исходников, ОС/DE, бэкенд, полный
список источников, фактический текст до/после и проверку отмены. Модульные
контракты IPC не заменяют проверку настоящего переключения и ввода.

### Базовое исправление

| Действие | Ожидаемый результат |
|---|---|
| Набрать `ghbdtn ` в английской раскладке | `привет `, раскладка русская |
| Набрать `руддщ ` в русской раскладке | `hello `, раскладка английская |
| Двойной Shift после ошибочного слова | Исправлено последнее слово |
| Тройной Shift | Исправлена фраза |
| Двойной Shift сразу после автоматического исправления | Возвращён исходный текст |
| Повторить отмену одного слова до порога в настройках | Слово появилось в исключениях |
| Поставить паузу, набрать тестовую строку | Текст не изменяется |
| Заблокировать и разблокировать экран | События блокировки не перепечатываются |
| Отключить и подключить тестовую клавиатуру | Работа возобновляется без перезапуска |

Проверьте исправление при быстром наборе и зажатом Shift, а также в полях
с автодополнением. Отдельно проверьте исключения по приложениям и
распознавание полей пароля, используя вымышленный пароль. Если приложение
не сообщает тип поля, перед чувствительным вводом требуется пауза.

В GNOME дополнительно проверьте исправление выделенного текста,
транслитерацию и число прописью. В KDE — виджет панели; в Sway/Hyprland —
Waybar и автозапуск из конфигурации композитора.

## Диагностика

`wayswitch dry-run` показывает решения без перепечатки;
`wayswitch run --verbose` выводит подробный журнал. Перед ручным запуском
остановите экземпляр службы, например `systemctl --user stop wayswitch`,
если она управляется systemd. После проверки запустите её снова.

Диагностические режимы показывают причины решений без набранных слов.
Вывод всё равно может содержать названия устройств и пути пользователя.
Используйте вымышленные сведения и просмотрите журнал перед публикацией.

`python3 tests/e2e_vm.py` — отдельный сквозной сценарий, не часть pytest.
Запускайте его с пустым тестовым полем в фокусе; он эмулирует нажатия.
Для проверки выходных evdev-событий этим скриптом временно задайте
`general.early_switch = false` и `backend.shell_typing = "uinput"`.
После проверки восстановите настройки. Режим печати через расширение
проверяйте отдельно по фактическому тексту в поле.

Для регрессии порядка событий GNOME 46 используйте `shell_typing=extension`
при активном RDP к локальному рабочему столу: три замены в каждую сторону,
`🚀: ghbdtn ` с кареткой после префикса, отмена, двойной Shift и парольное поле.
Проверьте, что Backspace применяются до вставки текста, префикс сохраняется,
а пароль не исправляется автоматически. `tests/e2e_vm.py` проверяет выходные
события uinput и не заменяет эту проверку IME-очереди расширения.

## Что приложить к отчёту

- Версии WaySwitch, дистрибутива и рабочего стола; тип сеанса Wayland.
- Имена и варианты раскладок, выбранный бэкенд из `wayswitch doctor`.
- Приложение, точные шаги, ожидаемый и фактический результат.
- Настройку задержки после смены раскладки, если её меняли.
- Диагностический вывод без личных данных.

Отправить отчёт можно в [GitHub Issues](https://github.com/Wetoshkin/WaySwitch/issues).

## Проверка полей LibreOffice, Chromium и Electron

Проверяйте настройки по умолчанию отдельно от обходных настроек. Счётчик
исправлений и смена раскладки не подтверждают, что текст дошёл до приложения.
В Writer и Calc сохраните документ и проверьте его содержимое, включая
пробел до слова и пробел после него. В браузере проверяйте значение поля.

| Приложение | Поля и переходы |
|---|---|
| LibreOffice Writer | Обычный абзац, заголовок, таблица, поиск и замена; новый документ без предварительного движения каретки |
| LibreOffice Calc | Редактирование ячейки, строка формул, поиск |
| Chrome | Адресная строка, input, textarea, contenteditable, редактор с role=textbox, readonly; первое обращение к доступности после запуска |
| Chrome/Electron | Обычное поле → пароль → обычное поле без ожидания опроса; пароль с изменённой ARIA-ролью и aria-activedescendant; Unicode перед вложенным полем |
| eXpress | Доступные поля исходного клиента и редактор сообщения в тестовой учётной записи; компонентный стенд отдельно от настоящего чата |
| Ptyxis | Автокоррекция выключена; ручной жест работает без истории и обучения |
| GNOME Text Editor | Обычное поле как контрольный сценарий |

### Calc в KDE: F2-редактор и границы

- В LibreOffice Calc откройте таблицу, выберите пустую ячейку, нажмите F2
  и наберите `ghbdtn `; при включённой автокоррекции сохраните документ.
  Ожидается `привет ` в этой ячейке, без дублирования исходного слова.
- Отдельно выключите автокоррекцию, повторите F2-ввод и двойной Shift.
  Ожидается `привет `, счётчик ручных исправлений растёт на один.
- Повторите автокоррекцию двойным Shift в F2-редакторе: ожидается возврат
  `ghbdtn `.
- Проверьте прямой ввод в выбранную ячейку без F2 (два прогона) и отмену:
  ожидается `привет ` и возврат `ghbdtn `, без дублирования.
- Обратное направление: в русской раскладке наберите физические `h e l l o`
  (на экране `руддщ`), ожидается сохранённое `hello `.
- Откройте поиск Ctrl+F и наберите `ghbdtn `: ожидается неизменённый текст
  поиска, без автоматического исправления и без роста счётчиков.
- Строка формул: щёлкните строку формул, наберите `ghbdtn `, Enter.
  Ожидается текст в ячейке как набран, без автокоррекции.
- Простая формула: введите `=1+1`, ожидается `2` без роста счётчиков.
- Формула с текстом: введите `="ghbdtn"`, ожидается текст `ghbdtn`
  без автокоррекции.
- В обе стороны проверяйте сохранённый документ, а не счётчик.
- Сложные формулы с текстовыми константами и Unicode, а также остальные
  приложения в Calc — отдельные непроверенные пункты.
- KF6-сборка Calc в текущей VM непригодна: VCL-плагин KF6 растёт до >4 ГБ
  и убивается OOM даже при 10 ГБ RAM. Проверки F2 выполняйте на той же
  версии LibreOffice с GTK3 VCL под KDE; это ограничение плагина, а не
  подтверждение поддержки KF6 Calc.

В редактируемых полях проверьте обе раскладки, ручное исправление, отмену
и соседние символы. В readonly и парольных полях автоматическая замена
отсутствует. Отдельно откройте системный диалог пароля поверх обычного поля:
фоновый снимок доступности не должен разрешать ввод в диалог.

В Writer оставьте включёнными раннее исправление WaySwitch и автозаглавные
буквы редактора. Проверьте первый абзац без префикса, непрерывный набор двух
слов и двойной Shift после ранней замены, пока оставшиеся буквы допечатываются.
Сохранённый документ должен содержать весь исходный текст после отмены.
Для замены через EditableText отдельно проверяются отказ, потеря фокуса
и неопределённый результат: повторной перепечатки и очистки поля быть не должно.

Если тестовый клиент требует учётную запись, отметьте непроверенные поля.
Проверка изолированного редактора на тех же библиотеках не заменяет проверку
настоящего чата с его обработчиками ввода.

## Права устройств и сеть

Issue #22: на Ubuntu 24.04 / GNOME 46 отдельно проверьте локальный вход,
RDP к существующему рабочему столу и отдельный удалённый сеанс. Запустите
службу без доступа к `/dev/uinput`: в журнале должно быть одно предупреждение
об ожидании, без traceback и роста счётчика перезапусков systemd. Верните
доступ локальным входом: запуск должен продолжиться без ручного restart.
При постоянном отказе `wayswitch doctor` должен указать на права и локальный
сеанс; `systemctl --user stop wayswitch` должен останавливать ожидание.
Сравните ACL до и после: служба не должна менять права устройств. Отдельный
RDP-сеанс не считается поддержанным этим исправлением.

Для Umbriel проверяйте настоящий сеанс с физическим устройством и клавиатурой
`uinput`; протокольная virtual-keyboard не заменяет эту проверку. После обычного
исправления проверьте первые синтетические клавиши сразу после блокировки,
старт демона на уже заблокированном экране и смену VT при ещё активном окне.
Буфер очищается; счётчики исправлений, история и обучение не пополняются.
Отдельно проверьте потерю IPC, ошибки logind и возврат в обычное поле: старый
префикс не восстанавливается. Замерьте задержку свежих проверок перед вводом.

Если после аварии реестра AT-SPI мост отвечает, но фокус не определяется,
перезапустите проверяемое приложение. До восстановления фокуса защищённое
автоматическое исправление должно ждать, ручное остаётся доступным.

На отдельной тестовой учётной записи сравните `getfacl` для тестовой клавиатуры,
мыши, тачпада и `/dev/uinput` до установки, после входа, при смене активного
пользователя и после удаления пакета с повторным входом. Проверяйте открытие
устройств вторым процессом только на тестовом оборудовании и вымышленном вводе.
Снятие ACL не отзывает файловые дескрипторы, уже открытые процессом.

Раздельно проверьте демон и GUI с включённым и выключенным автоматическим
поиском обновлений. Автоматическая проверка GUI обращается к GitHub Releases,
ручная кнопка проверки делает запрос и при отключённом автоматическом поиске.
Сетевой захват и журналы с машины пользователя перед публикацией обезличиваются.

## KDE: непрерывный ввод и первое слово после простоя

Эти проверки обязательны отдельно от исправления выделения и одиночных слов.
Зелёный CI не заменяет живой результат. 2026-11-08 проверки пройдены на
Plasma 6.6.6 для Writer KF6/GTK3 (см. итог в конце раздела).

- В Writer на Plasma Wayland проверьте отдельно KF6 и GTK3 с настройками
  WaySwitch по умолчанию. Наберите `Ghbdtn ` и сразу `vbh ` без паузы между
  словами. Ожидается ровно `Привет мир ` с обоими пробелами, без потери,
  дублирования и кратковременной вставки с возвратом исходного слова.
  Сверяйте документ, а не только счётчик службы. Повторите обе раскладки,

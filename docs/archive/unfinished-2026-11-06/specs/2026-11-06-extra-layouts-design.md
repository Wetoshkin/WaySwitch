# Issue №21: ru/en при дополнительных источниках ввода

Дата: 2026-11-06. Согласовано пользователем; реализовано, модульные проверки и ревью пройдены. Живая проверка Linux/DE не выполнялась.

## Задача и границы

Пользователь поручил разрешить установку, начальную настройку и запуск
WaySwitch на всех уже поддерживаемых платформах, даже если в графической
среде добавлены другие раскладки. Исправления остаются только ru ↔ en.
Дополнительные языки, словари и многоязычное определение текста не добавляются.
В интерфейсе и диагностике явно сообщается это ограничение.

## Подходы

1. Сохранять полный системный список и выбирать рабочую пару по исходным
   индексам — предлагаемый вариант. Единая политика ru/en используется
   контроллером, запуском и диагностикой; детали переключения остаются у бэкендов.
2. Отфильтровать список до двух элементов — отвергнуто: индексы бэкенда,
   keymap и композитора разойдутся, возможна порча текста.
3. Настраиваемые произвольные языковые пары — вне запроса; добавляет UI/config
   и поддержку языков, которых пользователь не просил.

Пользователь задал результат и область ru/en. Порядок выбора нескольких
вариантов и устройство общей политики ниже — предложения исполнителя.

## Поведение

- Список источников, порядок и индексы принадлежат графической среде:
  WaySwitch их не удаляет и не переставляет.
- Когда текущий источник — поддерживаемый русский или английский XKB-вариант,
  противоположным выбирается первый поддерживаемый источник другого языка
  в системном порядке. Текущий вариант сохраняется как источник преобразования.
  Новые настройки, запоминание последнего варианта и выбор языков не нужны.
- Английский определяется по идентичности/метаданным XKB, а не только по
  наличию латинских букв: de/fr/pl не становятся английскими; uk/be/bg — русскими.
  Существующие русские и английские варианты (включая Dvorak) сохраняются,
  если их фактические таблицы подходят для существующего преобразования.
- На другом источнике автоматические исправления, жесты изменения текста,
  преобразование выделения и обучение не выполняются. Возврат в ru/en
  возобновляет работу автоматически без ручного Resume.
- Внешняя смена источника сбрасывает буфер и контекст, отменяет отложенное
  исправление и защищает от переноса текста между раскладками.
- Без доступной пары ru/en приложение и служба могут работать пассивно:
  показывают причину, не изменяют текст. Нет циклов перезапуска только из-за
  числа раскладок. Реально отсутствующий IPC/сессия остаются ошибками подключения.
- Проверка раскладок завершается; дополнительные источники не блокируют
  кнопку продолжения мастера. При отсутствии пары выводится предупреждение.

Текст для пользователя: «WaySwitch исправляет ввод только между русской
и английской раскладками. Другие источники можно оставить в системе:
при их выборе WaySwitch не изменяет текст».

## Общие данные и бэкенды

- `keymap.py`: общая идентификация поддерживаемых групп и подбор пары;
  таблицы сохраняют соответствие исходным индексам. Не компилировать весь
  список в карту с возможным усечением групп: проверить 5+ источников на
  поддерживаемой libxkbcommon, при необходимости собирать таблицы по одному
  XKB-источнику. Неподдерживаемые IME — непрозрачные позиции без таблицы,
  никогда не подменяются рабочей ru/en-раскладкой.
- GNOME Shell: сохранять также позиции IBus-источников; `GetLayout`/`SetLayout`
  используют исходные индексы. IBus fallback не получает права считать
  неизвестный движок английским или продолжать старый буфер после его выбора.
  Существующая сверка IBus с композитором сохраняется.
- KDE Plasma, Sway, Hyprland: использовать их прямое переключение по индексу;
  тестами проверить пару на позициях вне 0/1, изменение списка и возврат из
  посторонней группы. Не требовать двух источников для пассивного запуска.
- COSMIC: использовать фактическую карту `wl_keyboard`, включая имена и
  таблицы групп; не пересобирать её по предполагаемым именам. Сохранять
  проверку подтверждения переключения и блокировку сеанса.
- Umbriel: снять проверку ровно двух источников; дойти до исходного индекса
  ограниченной последовательностью `keyboard-layout-next`. Каждый шаг
  подтверждать свежим состоянием, проверять неизменность списка и ожидаемый
  следующий индекс. При несоответствии/таймауте отказаться до удаления текста.
  Учесть события промежуточных групп, не выдавать их за неожиданный конечный
  переход. Сохранить защиту lock/VT/logind и всех обычных клавиатур.
- Hotkey / labwc / Wayfire / Cinnamon и среды, использующие эти fallback:
  не включать новые права авторежима. Учесть направление системного хоткея
  и ограничения двухгрупповых `grp:*_toggle`; не моделировать любой хоткей
  как циклический переход вперёд. При недоказуемом переключении оставлять
  пассивный режим с объяснением. Сохранять явно разрешённый пользователем
  режим `track_hotkey` только там, где последовательность можно корректно учитывать.
- Дистрибутивы и форматы пакетов используют ту же политику. Проверить
  NixOS, DEB/RPM, Arch, Flatpak/AppImage на отсутствие отдельного запрета;
  переносимые окна по-прежнему требуют нативную службу.

## Места изменения и риски для прежних пользователей

`wayswitch/keymap.py`, общие XKB-метаданные в `backends/xkbnames.py`,
`controller.py`, `daemon.py`, `doctor.py`, `gui/texts.py`, при необходимости
`gui/onboarding.py`; `backends/gnome_common.py`, `gnome_ibus.py`, `hotkey.py`,
`compositor.py`, `umbriel.py`, а также минимальные изменения однораскладочного
пассивного старта остальных бэкендов. Протокол Shell не менять без необходимости.
Обновить соответствующие тесты, фикстуры, README ru/en, `docs/PROGRESS.md`,
инструкции платформ и тестовый checklist, где они требуют ровно две раскладки.

Риски: спутать язык с алфавитом; потерять исходный индекс; задеть отмену,
CapsLock, ранние исправления и выделение; начать печать до подтверждения
многошагового переключения; потерять ввод при внешнем переходе.
Ранее работающие произвольные латинские раскладки с английским словарём
не должны рекламироваться как поддержка их языка. Отказ на них должен быть
видимым; подтверждённые английские варианты сохраняются.

## Проверка и готовность

Регрессии: us/ru/de и перестановки; 4 и 5+ источников; uk/be/pl/fr/IME;
несколько английских/русских вариантов; пустой/неизвестный/потерянный источник;
переход в постороннюю группу при отложенной замене и при undo; возврат в ru/en;
ручной жест и выделение; запуск без пары; мастер, статус и предупреждения.
Для каждого бэкенда — контракт текущего и целевого индекса, подтверждение,
отказ и смена списка. Для циклических — промежуточные события и зацикливание.

Запустить полный pytest и Ruff; проверки JavaScript, если он меняется.
Проверки реальной libxkbcommon выполнить в доступной Linux-среде без создания
новых виртуальных стендов. Живые проверки композиторов и пакетов отделять от
модульных и отмечать непроверенные платформы; не объявлять все среды
проверенными по одним симуляциям. Релиз и ответы в issue не входят в это
поручение; прежняя отсрочка 1.1.2 остаётся в силе.

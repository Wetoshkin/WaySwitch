# Заметки для ревьюера

Этот файл — не документация для пользователя, а карта для того, кто читает диф.
Он отвечает на три вопроса: **что читать в первую очередь**, **почему сделано
именно так** и **где автор сам сомневается**.

PR: `fix/numpad-keycodes-uinput-doctor` → `main`, 12 коммитов.
Ветка названа по первому багу (нампад), но выросла в переход на Wayland-only.

## 1. Как читать диф

По порядку, а не сверху вниз по списку файлов:

| Файл | Что это | Строк |
|---|---|---|
| `wayswitch/a11y.py` | новый: снимок фокуса через at-spi, поток опроса | 300 |
| `wayswitch/controller.py` | оркестрация: правила, защита, исполнение фикса | 603 |
| `wayswitch/detector.py` | чистые решения: раскладка, пунктуация, частицы, слипшиеся слова | 360 |
| `wayswitch/buffer.py` | буфер набранного: регистр, терминаторы (Tab/Enter) | 205 |
| `wayswitch/backends/kde_plasma.py` | новый бэкенд KWin через D-Bus | ~200 |
| `wayswitch/sound.py` | новый: сигнал после исправления | 79 |
| `wayswitch/gui/app.py` | окно настроек: экранная клавиатура, правила, программы | 586 |
| `packaging/install.sh` | установка: среды, pacman, toolkit-accessibility | ~150 |
| `wayswitch/data/*.gz` | словари, **генерируются** `tools/build_data.py` — не читать | — |

Тесты можно читать выборочно: `tests/test_focus.py`, `tests/test_auto_rules.py`,
`tests/test_sound.py` — новые; остальные дополнены по месту.

## 2. Как проверить

```bash
pip install pytest ruff              # или использовать venv проекта
python -m pytest -q                  # 277 тестов, ~1 с
python -m ruff check .               # чисто
```

Живые проверки без GUI (нужна сессия с настоящей раскладкой `ru`+`us`):

```bash
PYTHONPATH=. python3 tools/live_rules.py
```

Скрипт прогоняет семь сценариев тем же `Controller`, что в демоне, но печатающая
машинка только записывает: видно, сколько backspace-ов и какая раскладка
запрошена. Проверено на CachyOS/GNOME 51: 7 из 7.

Полная установка и проверка на живой системе:

```bash
sudo bash packaging/install.sh && systemctl --user enable --now wayswitch
wayswitch doctor        # все обязательные проверки должны быть ✓
```

## 3. Решения, которые выглядят странно, и почему так

1. **`settle_ms = 120` после смены раскладки.** Замер на живой системе: 30 мс —
   0/5 исправлений с пробелом, 120 мс — 5/5. Причина: приложение не успевает
   принять новый keymap и теряет последнюю клавишу серии. Альтернатива
   (`key_delay_ms = 15`) тоже работает, но замедляет всю печать.
2. **`SwitchLayout` до `Backspace`** (`actuator.plan_fix`). Если переключение
   не удалось, текст остаётся целым: стирать уже нечего.
3. **`verify_layout()` и отказ при расхождении.** IBus на GNOME 46+ меняет
   движок, но `mru-sources[0]` остаётся прежним, и исправление «проходит
   вхолостую». Лучше не исправлять, чем стереть слово и не напечатать новое.
4. **Опрос at-spi в отдельном потоке.** Синхронный D-Bus в пути ввода
   задерживает события клавиатуры (источник evdev в GLib не реентрантен).
   Контроллер читает снимок мгновенно.
5. **Снимок фокуса старше 3 с считается протухшим, и решение — fail-open.**
   Принцип: не мешать человеку и не терять функциональность из-за того, что
   мост доступности молчит. Ошибка в обратную сторону (запрет при отсутствии
   данных) выключила бы автоисправление у всех, у кого нет at-spi.
6. **Буфер берёт регистр из зажатых клавиш, а не из самого события.**
   Поэтому в тестах нельзя просто выставить `shift=True` в `KeyPress` — нужно
   нажать/отпустить `KEY_LEFTSHIFT`. Это неочевидно и уже один раз стоило
   мне часа отладки.
7. **Частичный фикс невозможен.** `_schedule_fix` сверяет снимок буфера
   (`last_word_with_tail`) перед исполнением; поэтому правило пунктуации
   переписывает слово целиком, а не «последнюю букву», хотя по смыслу меняется
   одна буква.
8. **`looks_like_word()` вместо `is_word()`** в правиле слипшихся слов: в
   русском левая часть почти всегда в падеже, которого в словаре нет
   (`сонату` нет, `соната` есть). Основа ищется префиксом через `bisect`.
9. **Правило слипшихся слов не трогает слова с заглавной в начале.** Иначе
   `WaySwitch`, `СбербанкОнлайн`, `Битрикс24` разваливались бы на два слова.
10. **`APP_ID` окна настроек отличается от D-Bus-имени демона.** Иначе
    `GApplication` падает на `Failed to register` и окно не открывается вообще
    (не «пустое окно», а ничего).
11. **Своё окно «О программе» вместо `Adw.AboutDialog`.** На libadwaita 1.10
    `present()` возвращает управление без ошибки и без окна. Плюс нужны
    кликабельные ссылки.
12. **Кэш списка приложений по `mtime`.** Файл нужен на каждом слове, но
    перечитывать его незачем; при этом правка подхватывается без перезапуска.
13. **`Tab`/`Enter` по умолчанию не завершают слово.** В терминале и IDE они
    выбирают автодополнение — перепечатка после них попала бы в другое место.
    Настройка есть, но включена осознанно выключенной.

## 4. Где я не уверен — прошу придирчиво посмотреть

**`wayswitch/a11y.py`**
- Поток опроса засыпает через 30 с без `poke()`. Гонка: `poke()` ставит
  `_wake` ровно в момент, когда поток уже решил выйти — флаг останется
  взведённым, а поток мёртвым; следующий `poke()` поднимет поток и сразу
  сбросит `_wake`. Проверьте, не теряется ли при этом одно обновление снимка.
- `_refresh()` ловит `Exception` целиком — скрывает настоящие баги. Стоит ли
  сузить до `GLib.Error`/`OSError`?
- `query_focus()`: обход в ширину, берётся **первый** не-оболочный
  сфокусированный узел. Если в дереве одновременно «в фокусе» два узла
  (попап + поле), выбор зависит от порядка обхода. Насколько это реально?
- `GetApplication` вызывается только для сфокусированного узла; если
  приложение не отвечает по D-Bus (таймаут 400 мс), вернётся `(None, False)` —
  то есть «ограничений нет».

**`wayswitch/controller.py`**
- `_apps()` кэш: `mtime` с точностью файловой системы. Быстрое «добавил —
  удалил — добавил» в пределах одной секунды может не подхватиться.
  GUI после правки зовёт `Reload` — проверьте, достаточно ли этого.
- `set_probe()` закрывает старый поток с `join(timeout=1.0)`. Может ли
  смена настроек прийти во время исполнения фикса, и что тогда произойдёт с
  `_pending`?
- `_focus_blocks()` вызывается и в `_on_word`, и в `_on_letter` (ранний
  URL-фикс). Правильно ли, что ручной жест (`tap_key`, двойной Shift) при
  этом не проверяется — то есть работает и в исключённых программах?

**`wayswitch/detector.py`**
- `split_words_fix`: `looks_like_word` отрезает до двух последних букв и ищет
  префикс. На коротких половинах (3 буквы) это может быть слишком мягко.
  Ложных срабатываний на восьми реальных словах не нашёл, но злые примеры
  приветствуются.
- `punct_fix`: `keymap.decode([last], other_group)` — что если в другой
  раскладке на этой клавише тоже буква (не пунктуация)? Проверка есть
  (`PUNCT_FROM_OTHER`), но набор знаков ограничен `,.;:?!`.
- `particles_fix` на длинных словах вида `абракадабрато` тратит лишний проход
  по словарю — не критично, но заметно.

**`wayswitch/buffer.py`**
- Ветка `_terminators` стоит **до** `RESET_KEYS`. Если `fix_on_tab = true`,
  событие `word` порождается, но `Tab` уже ушёл в приложение — фикс исполнится
  после того, как фокус, возможно, уехал. Это осознанный компромисс, но
  проверьте, нет ли способа отменить фикс, если после `Tab` пришёл `reset`.

**`wayswitch/sound.py` и демон**
- На каждое исправление создаётся поток. При быстром наборе их может быть
  несколько. Альтернатива — один воркер с очередью и «схлопыванием» частых
  запросов. Нужно ли?

**`wayswitch/gui/app.py`**
- `_add_current_app()` вызывает `a11y.query_focus()` прямо в главном цикле GTK:
  UI может подвиснуть до ~1.5 с (таймауты D-Bus). Вынести в поток?

**Бэкенды**
- `verify_layout()` — проверка «до», между ней и печатью есть окно (TOCTOU):
  человек может сменить раскладку мышью. Насколько вероятно и стоит ли
  перепроверять после `Backspace`?

## 5. Что заведомо не проверено на живой системе

- **KDE Plasma 6**: бэкенд покрыт юнит-тестами (`tests/test_kde_backend.py`),
  но на живой KDE-сессии не запускался — у автора GNOME.
- **Исключения по программам и поля паролей**: логика покрыта тестами с
  подставной пробой; живьём проверить не удалось, потому что Wayland не даёт
  программно поставить фокус в чужое окно (`Component.GrabFocus` → False,
  `DoAction` по полю фокуса не даёт, интерфейса `org.a11y.atspi.Window` у
  GTK4 нет вообще). Нужна ручная проверка.

## 6. Что тут можно выкинуть, если покажется лишним

Самые «необязательные» части, без которых ядро работает:

- `wayswitch/sound.py` и `sound_on_fix` — украшение;
- правило слипшихся слов (`split_words_fix`) — самое эвристическое;
- экранная клавиатура (`gui/gesture_keys.py`, `gui/keyboard_picker.py`) —
  можно заменить обычным полем ввода;
- KDE-бэкенд — если решим, что поддерживаем только GNOME.

Ядро: `keymap` → `detector` → `controller` → `actuator` → бэкенд, плюс
`a11y` для исключений.

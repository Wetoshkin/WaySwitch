# Обновление WaySwitch

Описанный здесь интерфейс реализован в исходниках после 1.1.4 и пока не
входит в опубликованный выпуск 1.1.4.

Откройте **Параметры → Система → Обновления…**. Окно показывает источник
установки, установленную версию и результат проверки. Для GitHub-выпуска
там же доступны заметки об изменениях. Для пакета дистрибутива сведения об
изменениях предоставляет его сопровождающий или пакетный менеджер.

**Установить через терминал** запускает обновление через прежний источник.
В терминале видны предлагаемые действия, запросы подтверждения и пароля,
а также ошибки. После успешной установки проверяется результат. Ранее
работавшая нативная служба перезапускается и подтверждает версию по D-Bus;
выключенная служба не включается. Затем окно запускается заново. При ошибке
установки или проверки работающее окно остаётся открытым. Если средство
перезапуска окна недоступно, терминал предлагает открыть его самостоятельно.

**Скопировать команду** позволяет выполнить обновление в своём терминале.
Для нативной установки это обычно `wayswitch update --install`: команда
заново определяет источник и проверяет наличие обновления. Без `--install`
она только показывает результат проверки и команду, ничего не устанавливая.
При ручном запуске после завершения закройте и снова откройте окно.

## Источник сохраняется

| Установка | Проверка и обновление |
|---|---|
| Наш DEB/RPM из GitHub Releases | Пакет выбранного выпуска и `SHA256SUMS`; установка через подходящий пакетный менеджер без перехода к исходникам |
| Наш сетевой установщик, установка из исходников | Исходники конкретного тега GitHub с проверкой разрешённого коммита |
| AUR с обозначенным источником | Версия рецепта AUR, включая epoch/pkgrel; установленный `paru` или `yay` с явным `aur/имя-пакета` и обычным просмотром изменений |
| AUR без помощника | Команда получения рецепта, просмотр файлов и подтверждение перед `makepkg -si`; помощник не устанавливается автоматически |
| ALT/Сизиф и другие репозитории | APT-RPM, APT, DNF или Zypper по владельцу установленных файлов и настройкам менеджера пакетов |
| Репозитории Arch | Проверка локальных метаданных pacman; команда системного обновления с явным пояснением, без автоматического запуска всей транзакции |
| AppImage | Проверенная загрузка и замена собственного файла через временный файл в том же каталоге; нативная служба обновляется отдельно |
| Flatpak из репозитория | Команда `flatpak update io.github.Wetoshkin.WaySwitch.Gui` для запуска на основной системе |
| Скачанный файл `.flatpak` из GitHub | В окне выберите «Я устанавливал скачанный файл .flatpak…»; появятся заметки выпуска и команда проверенной загрузки для основной системы, с сохранением пользовательской или системной области установки |
| Atomic-система | Явная ручная команда для развёртывания или замены локального RPM; может потребоваться перезагрузка |
| Nix/NixOS | Обновление пакета или закреплённого источника в собственной конфигурации и обычная пересборка |
| Неизвестный источник | Инструкция использовать прежний способ; другой источник автоматически не выбирается |

Проверка стороннего репозитория использует доступные менеджеру метаданные;
они могут требовать обновления через системный центр обновлений. Новая
версия на GitHub не означает, что сопровождающий уже подготовил её в
Сизифе, AUR или другом репозитории. Учитываются и исправления упаковки без
смены версии приложения. Ошибка проверки не считается отсутствием обновлений.

После обновления метаданных менеджер может установить пакет новее показанного
кандидата. Проверка результата репозиторной установки учитывает порядок версий,
включая epoch и ревизию RPM. Пакет старее кандидата или ошибка сравнения не
подтверждают успешное обновление и не запускают перезапуск службы.

Пакет, собранный вручную для Arch, нельзя достоверно отнести к AUR только
по имени. Старой установке без обозначения источника может потребоваться
одно обновление прежним способом. Сопровождающим доступен
[контракт упаковки](aur.md#обновления-в-сторонних-репозиториях).

## Окно и служба

Flatpak и AppImage содержат окно настроек, а исправление ввода выполняет
отдельная служба на основной системе. Окно показывает её версию, если
служба передаёт это поле. Для службы можно скопировать
`wayswitch update --install` и выполнить на основной системе. Если служба
ещё не поддерживает эту команду, обновите её прежним способом. Источник
окна не определяет источник службы.

Flatpak не получает новых разрешений на выполнение команд основной системы.
Если он не может определить происхождение своего пакета внутри песочницы,
выбор скачанного пакета GitHub делает сам пользователь. Этот выбор действует
в текущем сеансе окна. Если пакет отмечен сопровождающим как внешний,
такой переход не предлагается.

В AppImage без доступного исходного пути или прав на каталог замена не
выполняется автоматически. Команда скачивает проверенный новый файл в
текущий каталог, не перезаписывая существующий. Закройте окно и замените
файл вручную. Команда `AppImage --appimage-extract-and-run --update`
позволяет запустить обновление переносимого окна из терминала.

После обновления расширения GNOME может потребоваться выйти из сеанса и
войти снова. Неприменённое atomic-развёртывание требует перезагрузки;
приложение не перезагружает систему автоматически.

## Сеть и настройки

Переключатель уведомлений находится в **Параметры → Система**. Фоновая
проверка выполняется при запуске и затем раз в сутки; явная кнопка проверки
работает и при выключенных уведомлениях. GitHub-установка обращается к
GitHub API, AUR — к RPC AUR с именем пакета. Пакеты сторонних системных
репозиториев проверяются через их менеджер без обращения к GitHub.
Введённый текст и содержимое конфигурации в эти запросы не передаются.
